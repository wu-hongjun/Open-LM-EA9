# UI audit: two-card Device view

## P1: Misleading state or copy

1. **"Verified" can show for a plain read.** In `DeviceOverview`, the caption falls back to `currentFirmwareObservation?.readAt` and still says "Verified". Say "Read …" for observations. Keep "Verified" only for `verifiedAt`.
2. **The Firmware row can show stale data.** The applied-lens version takes priority over a fresh observation. Prefer the latest observation, or show the row only when the two agree.
3. **"Cancel operation" runs `cancelBackup` during any busy state, including firmware upload.** Show it only for backup reads. Never imply that an upload can be safely cancelled.
4. **Recovery copy assumes a backup exists.** "…remains available from this adapter's verified backup" shows even when `lastBackup` is nil. Make it conditional, or say a verified backup is required.
5. **The firmware section hardcodes "Biotar 58mm f/2".** The library id is `zeiss-jena-biotar-55-f2`. Take the name and focal length from the compiled setting so the two can't disagree.
6. **The firmware section doesn't show what is installed.** The 4.5 button is hidden when 4.5 is current, but nothing says "Installed". "Install 4.6.0 candidate…" stays visible even when 4.6 is installed. Add an Installed marker per row and hide the install button for the current variant.
7. **The fallback `workflowDetail` mentions "Refresh"**, but no Refresh control exists in this UI. Remove that sentence.
8. **The empty Lens card says "Read the adapter in USB tools."** even when no adapter is connected. Tell the user to connect first when `!adapterConnected`.

## P2: Redundancy and slop

9. **Remove the "Library" link on the Lens card.** It duplicates the header tab.
10. **The banner's "Review" button and the card's "USB tools" button do the same thing.** Keep one label, "USB tools".
11. **USB tools sheet:**
    - Remove the wrapper `VStack` around the title.
    - The "Firmware updates" disclosure contains a second "Firmware" heading. Drop the inner `Label`.
    - Wrap either both disclosures in `Surface` or neither. Currently only Recovery is wrapped.
12. **Drop repeated or decorative copy:**
    - "The physical iris stays manual." repeats the Lens card.
    - Keep "Physical aperture: Unknown" plus a single "Set the iris with the lens ring."
    - Remove the library footer "Lens details are saved on this Mac." The editor footer already says it.
    - Remove the editor's `Eyebrow` family label and serif name.
13. **Empty Lens card:** shrink the 74pt ultralight placeholder icon to match the photo height, or drop it. It's decoration.
14. **Move the progress block to the top of the sheet**, next to the status pill. At 670pt tall it can sit below the fold while it's the only active element.

## P3: Native fit (worth doing now, low risk)

15. **Fixed light colours break Dark Mode:** `Palette`, the white `Surface`, and the cream canvas. Use semantic colours (`.background`, `.secondary`, `.separator`) and a smaller corner radius (about 10–12).
16. **The custom tab capsule** could be a native segmented `Picker` in the toolbar, with the same two tabs: Device first, Lens Library second.

## Keep as is

- The two-card `HStack` layout and the adapter photo.
- Connection pill, Firmware row, compiled lens name, "Sony aperture dial" range, and "Physical aperture: Unknown".
- The banner shown only for actionable states (`needsWorkflowBanner`).
- Reconnect acknowledgement and its one-line caption.
- Gating of read and verify actions.
- Backup copy: "Two full reads are compared before your private backup is saved."
- Recovery hidden behind a disclosure.
- 4.6 copy: "Prepared offline; camera validation is pending." Keep it as written and don't add camera claims.
