# Astra 14 — frozen 3.3 whole-chain stack and interrupt audit

The frozen 3.3 compiled application has a **1,560-byte conservative conditional
stack bound**, including an intentionally broad six-exception envelope, against
its **8,192-byte linker reservation**. This is not measured high-water or an
unconditional claim that the stack is safe on the adapter. Existing stock
bootloader reconstruction establishes the intended MSP/vector handoff: entry
`0x2510` loads MSP from the application vector and sets VTOR to `0x5000` before
calling its reset vector. Remaining entry gaps are CONTROL/PSP selection,
PRIMASK, inherited interrupt state and physical execution of that reconstructed
path. Only EIC's priority is explicitly programmed by the application. No stack
overflow or recursive call path was demonstrated in this audit.

Scope follows the [eight-hour ledger](../firmware-hardening-2026-10-15.md) and
[3.3 evidence](../evidence/upstream-33-hardening-2026-10-15.md). The work reads
the existing `build/final-33a` source, ELF, map and `.su` files; it does not rebuild
or modify the frozen firmware. No device discovery, HID, USB, updater, flash,
motor, network, Git or canonical Application Support action occurred in this lane.

## Compiled paths, callbacks and library coverage

The graph contains 137 linked function bodies and 449 direct/reviewed-indirect
call or inter-function branch sites. All 14 register-indirect sites have reviewed
targets or proven-empty linked callback tables. No unresolved compiled edges,
dynamic `.su` frames or graph cycles remain under the intact-data assumption.
Dead functions present in `.su` are not counted as reachable; compiler-generated
`.isra.0`/`.constprop.0` symbols are matched to their GCC stack records.

| Indirect sites | Actual targets / evidence |

| Shutdown `0x55e6` | `powerdown_signal`; sole nonzero registration in `main` |

| Runtime `0x50c4`, `0x50ec` | Unreachable weak callbacks: linked literals are zero and clone endpoints equal |

The release's servo configurations are `STOCK` and local `sweep`/`drv` copies;
the copies change scalar speed parameters, retaining callback pointers. The
legacy park configuration/function and park setter are absent from the linked
release. The old `em_poll` comment about a park callback recursively pumping
polling describes a path removed by the shutdown lane. In this ELF, `pump`
can call `em_poll`, but no poll/shutdown callback calls back into servo or `pump`.
CS and VD callbacks run sequentially within one EIC entry. An asserted flag or a
second pending interrupt can cause later entries, not recursive same-priority
handler nesting.

Seventeen runtime/library bodies have no application `.su` record. They were
reviewed in the pinned disassembly and assigned conservative local frames:
clone registration/deregistration, global destructors and `frame_dummy` 8 bytes
each; switch helpers 4; division bodies 8 including divide-by-zero push paths;
division-mod wrappers and divide-by-zero leaf 0; `memcpy`/`memmove` 8; `memset` 0;
`__libc_init_array` 16; `_init`/`_fini` 24. The mod wrappers' inter-function
branches retain their target division-body frame in the graph. Switch helpers
return to intra-function jump-table targets and restore their four-byte scratch
push. No library frame is silently treated as zero because `.su` is absent.

For every edge the analysis sums the caller's maximum frame and the largest
child chain. It charges tail branches as if both complete frames remain,
which can only overestimate these reviewed paths. It does not assume that
maximum frame use and the worst child call occur at the same instruction.

## Whole-chain bounds

| Root / envelope | Bytes | Interpretation |
| --- | ---: | --- |
| `main` and its deepest child chain | 1,140 | Includes failure handling below transmit |
| `Reset_Handler` through `main` | 1,156 | Includes the live 16-byte reset frame |
| EIC software chain | 156 | EIC → CS → shutdown admission → frame validation |
| SERCOM1 software chain | 32 | Handler → inhibit-fault → lock |
| SysTick / default dummy handler | 0 | Hardware exception frame still applies |
| Foreground + reset-priority normal IRQ envelope | 1,416 | EIC plus one of SERCOM1/SysTick, two hardware frames |
| Foreground + all three active IRQ chains | 1,452 | Arbitrary inherited priorities, three hardware frames |
| Foreground + every configurable priority level + HardFault + NMI | **1,560** | Six hardware frames plus all three nonzero/active software chains; conservative overcount |

The longest foreground sum is:

```text
Reset_Handler 16 → main 104 → focus_exec 96 → focus_run.isra.0 112
→ servo_move_rel 136 → pump 8 → em_poll 56 → em_pump_status 40
→ em_transmit 304 → delay_us 16 → st_fail 24 → st_flush 112
→ append 104 → st_write_page 28 = 1,156 bytes
```

This deliberately includes a peripheral wait exhausting its budget and entering
the diagnostic fail-stop while a servo/poll/transmit chain remains live. It is
substantially different from quoting the largest single frame, 304 bytes.
It also overcounts interrupt overlap with the deepest diagnostic tail:
`st_fail` disables maskable interrupts before `st_flush`, and `st_flush` holds a
saved PRIMASK lock through its append sequence. No reduction for those masks is
needed to obtain the reported bound.

The core exception allowance is eight 32-bit words plus a possible four-byte
alignment word, **36 bytes per active exception**. There is no floating-point
exception context on this Cortex-M0+. Same-priority and lower-priority pending
interrupts cannot preempt an active handler. Tail-chaining does not accumulate
one frame per pending event. The local SAMD21 definition supplies two priority
bits, hence at most four simultaneously active configurable-priority levels;
HardFault and NMI supply the additional two levels. All other implemented vector
slots point to the zero-local-frame infinite-loop `Dummy_Handler`; reserved
zero slots are not treated as callable functions. The all-vector envelope uses
all three application ISR chains plus six exception frames even where EIC's
fixed priority prevents that exact combination. It is a conservative envelope,
not an asserted executable worst-case schedule.

## Interrupt state, remaining gates and action

The compiled application enables EIC (IRQ4), SERCOM1 (IRQ10) and SysTick.
`em_eic_init` explicitly sets EIC priority 1 (`0x40` on this implementation).
`em_uart_init` enables SERCOM1 without writing its priority; `delay_init` enables
SysTick without writing its system priority. At reset defaults, both are priority
0, so either can preempt EIC, and they cannot preempt one another. A bootloader
jump is not itself a processor reset. The existing
[stock boot reconstruction](../reverse-engineering/stock-boot-reconstruction.md#startup-and-architecture)
records PA23-low startup invoking `0x2510`, loading MSP from `[0x5000]`, setting
VTOR to `0x5000`, then calling the reset vector. The
[boot inventory](../reverse-engineering/stock-boot-inventory.csv) labels
`0x2510–0x2527` as `application_vtor_msp_handoff` with high confidence (evidence
`ev_af84eb17e704f414c6a70060f43666c376cc40e1828175a44552db137154b0c6`).
That prior static evidence resolves the intended MSP load and vector assignment;
it is not a fresh physical observation. Neither Reset_Handler nor main clears all
inherited NVIC enables/pending bits or normalizes all priorities. Thus the
1,416-byte normal envelope requires reset-like interrupt state; use the broader
1,560-byte conditional envelope until the remaining entry/interrupt state is
established.

Three compiled routines manipulate interrupt masking: `st_lock` reads PRIMASK and
executes `cpsid i`, `st_unlock` restores the saved PRIMASK, and `st_fail` executes
`cpsid i` permanently. There is no application `cpsie i`, MSP/PSP write or CONTROL
write. Restoring a saved key preserves an outer mask; it does not itself create
higher interrupt nesting. NMI/HardFault remain possible while PRIMASK is set.
This audit makes no cycle, interrupt-latency or NVM-duration claim.

The vector's initial SP is `0x20002c08`. Linker symbols reserve
`[0x20000c08, 0x20002c08)`, immediately above 3,076 static RAM bytes and four
alignment bytes. The 1,560-byte model leaves 6,632 bytes of that reservation
unused. The linker reservation is not a runtime guard, a measured low-water
address. The reconstructed stock path loads this vector SP, supporting the
intended application reservation and replacing the prior bootloader MSP rather
than retaining its call stack beneath the application. The supplied reconstruction
does not establish CONTROL/PSP selection, PRIMASK or all enabled/pending interrupt
state, and it explicitly retains physical boot/app-handoff validation as open.
Consequently the MSP load is statically established, while actual execution of
that path and use of MSP for thread-mode application frames remain acceptance
conditions for applying the bound to a physical run.

**Actionable follow-on:** retain the resolved stock MSP/vector handoff and close
the exact remaining CONTROL/PSP, PRIMASK, vector-transition interrupt state and
enabled/pending/prioritized interrupt conditions; separately validate physical
execution of that path before promoting the conditional bound to an on-device
guarantee. A separately
versioned executable could explicitly normalize the intended interrupt priorities
and entry state if that contract requires it. Keep 3.3 frozen. A future separately
authorized physical test should collect stack high-water/guard evidence across
startup, capture, motion, shutdown and injected fail-stop; it remains a separate
acceptance gate. Neither a large arithmetic margin nor this audit establishes
camera behavior, ISR timing, physical motor rest or safety after memory corruption.
