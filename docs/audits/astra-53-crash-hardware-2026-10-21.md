# AF4.1 hardware/reset audit — 2026-10-21

Status: passed conditional final AF4.1 compiled audit. This is strictly offline evidence; no adapter enumeration, USB/HID access, motor execution, flashing, app/updater launch, or canonical Application Support access occurred. Historical evidence is read-only.

The implementable minimum is a CRC-protected retained checkpoint, an independent-clock watchdog serviced by bounded foreground progress, and one append-only recovery page before normal initialization. WDT/SYST reset must stop before protocol initialization and normal motor initialization/drive even when the checkpoint is corrupt or the tail is full. A system reset is not proof of HardFault. Recovery is not guaranteed across power loss, lost clocks, failed exception entry, or bootloader failure.

WDT channel is GCLK ID3. Generator4 sourced from OSCULP32K divided by32 gives nominal1024Hz; PER_4K gives nominal4s. Oscillator tolerance prevents treating that as an exact deadline. Generator ownership must be exclusive. Normal mode, no early-warning IRQ, no ALWAYSON, and no fuse modifications are the minimal contract. CONFIG is enable-protected. CTRL and CLEAR synchronize; a write while busy can stall the bus. Setup must poll before writing, health must skip busy CLEAR, and all software waits must be finite. Finite poll loops cannot bound a stalled bus access itself. WDT pauses under debugger halt. It can recover CPU/foreground deadlock only while its clock/power/reset machinery remains functional.

ALWAYSON can originate in the user row. Code must reject or explicitly handle this state, because writing CTRL=0 cannot disable it. A normal WDT/SYST reset resets ordinary WDT configuration while preserving specified special reset domains; the implementation must not assume all generic clocks are pristine after every possible handoff.

## Bootloader and retained memory

A hardware reset fetches vectors at0x0, not the application VTOR. The pinned original bootloader SHA-256 is `8b6cb0bca7572748ddc1ba85bcb58ef261b8799898603e9b86a0ba4cb038c895`. A conventional app `.noinit` immediately after its approximately3KB BSS would overlap boot stack use.

The new [runner](../../firmware/upstream-hardening/followup/53-crash-hardware-audit/boot_retention.py) reuses lane24's original-instruction Unicorn fixture, stops at application reset entry, records SRAM writes, and preloads WDT RCAUSE. The [result](../../firmware/upstream-hardening/followup/53-crash-hardware-audit/boot-retention.json) has two calibration fixtures:1170 SRAM writes each, exclusive high address0x20001690; top128-byte sentinel survives. The normal path does not read RCAUSE and preserves its WDT value. Thus0x20003000 or0x20003f80 is outside this bounded boot write set. This is an executable path result, not exhaustive whole-boot proof. DMA, asynchronous exceptions, electrical state and timing are absent from the inherited model.

The checkpoint needs a fixed linker NOLOAD reservation excluded from data copy, BSS clear, app stack, and heap. Exact compiled symbols must establish that exclusion. CRC/magic/version reject random or torn contents; SRAM retention through powered reset remains a conditional engineering assumption, not a power-loss persistence guarantee. Mixed POR/BOD with WDT/SYST rejects retained payload while still selecting conservative fail-stop for the crash-cause bits.

Boot branches on PA23, not reset cause. Low launches the app; high stays in USB runtime with no ordinary later recheck. Boot readiness polling can also prevent handoff. Consequently app recovery cannot be guaranteed on every watchdog event. The app must not add a reset/homing loop: recovery checks happen before board/protocol/motor initialization, append at most one page, then stay quiescent. Normal terminal paths must make the motor safe before flash or reset.

## Flash and exception constraints

Main-array reads during programming stall AHB. Flash-resident instructions/vector fetches and handlers therefore cannot be assumed to service a live bus during a page write. The original finite READY budget does not cap a flash-fetch stall. Do not add active-session NVM writes or an early-warning flash ISR. Pre-protocol reset recovery avoids this live timing dependency; existing terminal writes remain terminal only.

Only erased64-byte pages in `[0x9c00,0xa000)` belong to the diagnostic tail. Preserve the16-page bound, alignment, full-page erased check, PBC/WP-only command set, halfword-addressed ADDR, word page-buffer stores, read barrier, status check, and readback. No erase, unlock, auxiliary/user-row or metadata write is permitted. A torn page consumes its slot; CRC rejection is not permission to overwrite it. Full tail means no write and fail-stop, not wraparound. Repeated crashes consume finite slots; no wear endurance or power-fail atomicity is established by host tests. A checkpoint committed immediately before reset may be older than the fault; its timestamp is a last-completed checkpoint, not a crash timestamp.

For Cortex-M0+, avoid M3/M4 fault-register assumptions. Minimal HardFault handling may issue AIRCR SYSRESETREQ from a naked, stack-independent sequence and use the previous validated checkpoint. It must not dereference a potentially corrupt stacked frame. PC/LR capture would require explicit EXC_RETURN/MSP/PSP validation, aligned in-SRAM bounds for all eight stacked words and a policy for failed stacking; omit it at this budget. The exact handler needs ARMv6-M instruction inspection and vector binding. Even a naked handler cannot guarantee execution when exception entry itself fails.

## Required final review

Confirm exact build hashes, code end at most0x9b00, reserved tail untouched,8192-byte stack, retained section exclusion and source manifest; inspect reset ordering, terminal cutoff, all watchdog CLEAR call sites, generator4 ownership, no unwanted IRQ/fuse writes, and naked handler instructions. Foreground service requires advancing tick plus completed bounded work. Servo retargeting can extend a motion beyond nominal4s, so main-loop-only feeding risks false resets; a feed after a completed bounded sensor/control iteration is acceptable. Feeding from SysTick, arbitrary IRQs, or the middle of a blocking wait hides the faults under investigation.

A persistent CRC-valid type5 WDT/SYST record can latch future cold boots off until the tail is cleared by an explicitly authorized image operation. A full tail fails closed on boot, and any occupied page with a bad CRC latches a storage-fault halt on future boots. A failed write that leaves its page wholly erased leaves no durable evidence; a later POR can therefore lack the latch. This is a persistence limitation, not an authorization to retry programming the torn page.

The boot fixture now supplies pinned APBAMASK/APBBMASK reset values0x7f instead of treating those two registers as zero. Both remain0x7f at app reset entry in both fixtures: WDT APBA bit4 and PORT APBB bit3 are enabled. Explicit APBA WDT enable before the first WDT register access is nevertheless recommended; it requires no synchronization wait. Emergency GPIO release must precede an ALWAYSON incompatibility halt. This boot result supports the existing early PORT-access assumption under the ordinary reset contract.
