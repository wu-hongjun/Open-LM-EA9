# Astra lane 08 — diagnostics, retention and decoder boundaries

Offline proposal against frozen upstream C 3.2 (`e20f169d9476391a1b988da5122f534411ceecc6b282e7acb92b558256a7c0df`). Root owns integration/publication. No device enumeration, USB/HID traffic, updater, hardware motion, flash or Application Support changes occurred. Published images and original recovery are untouched.

## Findings and proposed disposition

1. **Remove inferred-silence NVM writes.** Frozen `emount.c` flushes after two seconds without VD during its CS wait; `main.c` flushes after an incomplete handshake and 100 ms without a frame. Neither predicate excludes a delayed or resuming healthy camera. The lane overlay removes both. Its only remaining production calls are the existing terminal shutdown path after `em_uart_disable()` and `st_fail()` with interrupts disabled and motor GPIO released. No replacement quiet window is introduced. Blank logs after a nonterminal hang or battery removal are an explicit tradeoff.
2. **Retain terminal evidence after startup traffic.** Frozen storage preserves the first 48 events only. Ordinary CS/RX/TX events fill that budget, so later capture, fault and shutdown notes disappear even while summary counters continue updating. The proposal keeps the first 24 and last 24 events in the existing 576-byte array, using an index rotation without shifting/division in the IRQ path. RAM eviction is saturating-counted. This improves recent evidence but does not guarantee an earlier capture remains after subsequent traffic.
3. **Write the summary first.** With only one remaining append slot, frozen flush writes four old events and loses the summary. The same loss occurs whenever pending event pages consume the remaining budget. The proposal writes the summary to the first available slot, and counts event-budget omissions alongside RAM evictions. A later torn event page therefore cannot destroy an already-written summary. Its planned event count is not a claim that later programming completed; the decoder separately counts surviving same-boot events and marks incomplete snapshots. With one slot available the output is a summary only, including a shutdown-UART-disabled flag and the existing fault/counters. With few slots the serialized event prefix can exclude the recent-event segment; the summary reports the omission.
4. **Make terminal flush one-shot.** Repeated calls currently consume additional summary slots and can mix an old frozen event list with later counters. The proposal seals the snapshot once a permitted flush begins. Write/read failure still stops the writer permanently for that boot; there is no retry or corrective programming. A fresh physical boot scans occupied/torn slots again.
5. **Report actual append availability.** Existing decoder `storageFull` means every physical page is non-erased. Firmware instead appends strictly after the highest occupied/torn page. A torn last page with 15 earlier erased holes has zero append capacity while `storageFull` is false. The extension preserves the old field and adds append frontier, appendable pages, stranded erased pages and append-exhausted state. The record `boot` is a slot-derived generation marker, not a physical reboot counter.
6. **Bound observed-capability facts.** The frame admission proposal fixes command handling, but frozen diagnostics still infer message 08 capability presence from raw window length. Two actual production-dispatcher tests reproduce checksum/padding contamination for valid 9/10-byte frames in larger windows. The overlay reads a two-byte RX operand only when validated `view.length >= 11`; a dedicated `ST_CAPABILITY` note records the observed byte under that same guard. This is explicitly an observation, not accepted/negotiated state: lane07 commits negotiation only when its owned ordinary request is consumed. Decoder v2 calls the field `observedMessage08CapabilityByte` and gives that distinction; legacy v1 output stays compatible.
7. **Preserve nonterminal inhibit reasons in RAM.** A low-cost `st_inhibit_fault(reason)` latches the first reason without timestamps, allocation, event churn or NVM. Calls cover fatal UART RXC drain, home failure, motor/servo work budgets, runaway/wrong-way and encoder overflow. They do not mark deliberate shutdown inhibition as a fault. Existing terminal `ST_FAULT` notes may supersede the summary reason. This improves a later successful terminal snapshot; it does not persist an inhibit that ends in battery removal.

## Overlay and format

`firmware/upstream-hardening/lanes/08-diagnostics/apply.py` exposes `apply(work: Path)`, refuses the frozen build directory, and operates only on staged sources. It is tested after frame/TX base applicators and lanes 02, 01, 03, 05, 06 and 07. Lane06 replaces the root motor applicator; do not apply both. It does not edit the NVM writer, linker storage range or any existing release.

The application log remains `[0x9c00,0xa000)`, 16 pages of 64 bytes, append-only, without erase. Records keep `E9S2`, field layout, slot binding and CRC32, with record format byte changed to **2**. Existing v1 summary fields retain their offsets. New summary payload bytes are: 33 retention-policy value `1`; 34 buffered event count; 35 planned event count; 36 observed shutdown-UART-disabled boolean. `droppedEvents` includes RAM evictions plus planned capacity omissions and saturates at 65535. It does not count wire frames never admitted to the trace. The summary is written first. A later write failure leaves that summary with its original plan; the decoder marks missing/torn event data rather than claiming the plan succeeded. If writing the summary itself fails, no event pages are attempted.

The new snapshot is at most 12 event pages plus one summary. A first full snapshot leaves only three pages; later boots have much less history. Full/torn pages are never reclaimed and all erased holes below the append frontier remain unused. This limitation is intentional and bounded. No diagnostic erase or log-reset command is proposed.

## Decoder and installation/recovery boundary

`apply_decoder.py` installs the extension into a staged repository copy. The shared decoder is not edited by this lane. The original v1 parser remains available and 3.2 decoding is bound to the hardcoded immutable full-image digest above. A 3.3 native backup must report exactly version 3.3.0 and its exact application prefix `[0x5000,0x9c00)` must match the pristine candidate bytes.

3.3 resolution requires a published `firmware/candidates/3.3.0/contax-zeiss-50-f1-4.bin`, its adjacent published manifest, and an explicit `firmware/candidates/diagnostic-registry.json` entry. That entry independently pins **full image SHA-256, full manifest SHA-256 and immutable prefix SHA-256**. Missing entries/pins fail closed. Root must populate them only after the final candidate is frozen; this lane supplies no invented 3.3 digest or publishable registry. The pristine template must have an entirely erased 1024-byte log tail. A synthetic registry/image exists only in private test output.

A supplied native backup manifest still requires two flash reads, two auxiliary reads, the complete 128 KiB size, and its full-flash hash. Raw 128 KiB inputs are supported and explicitly report that no backup manifest was matched. Unknown versions, altered prefixes, template/manifest pin mismatches and incomplete dumps fail. Corrupt or structurally impossible pages remain invalid/torn. v2 pages are not accepted as 3.2 records.

This is an **offline diagnostic-read exception for the log tail only**. It does not verify installation, original firmware, user-row identity, keys, bootloader or recovery authorization. The result explicitly reports `installationVerificationPerformed: false`. No installer, reconnect verifier or recovery code is changed; they must retain full-image byte verification. A diagnostic prefix match cannot substitute for that gate.

## Limits and deferred hardware questions

No persisted record proves camera acceptance or exposure completion. `shutdownUARTDisabledObserved` proves only reaching that firmware point if its page survives; it does not prove PA23 signaling, actual power removal or clean next power-on. Conversely, battery removal, power loss during flush, an unentered terminal path, exhausted storage, boot-time read failure or writer error can leave no useful record. A blank region cannot establish “the firmware never ran.”

IRQ masking around flush can lose SysTick time; event timestamps are firmware counters, not calibrated elapsed durations. The bounded READY iteration count is not a physical programming-time guarantee. Existing AHB barriers/readback and supplied READY states are exercised only at the instruction/model level. Actual NVM cache coherence, voltage/brownout behavior, write duration versus the body's powerdown budget, programming endurance and failed-write retention remain unmeasured. Sixteen available slots bounds writes per erased image, not lifetime endurance across reinstallations. No writes were added to active healthy communication to improve observability.
