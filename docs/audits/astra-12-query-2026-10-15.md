# Follow-up 12 — query ownership and bounded service

A source-path audit after frozen 3.3 reproduces **an old-session query answer
appearing in a new session's 0x06 status tail**. A separate finite stream test
services 65 conversions in one foreground pass while the answer queue holds only
four. The proposed worker services at most `EM_QUERY_Q` (four) per pass and
publishes an answer only if its captured epoch/readiness still belongs to the
current session. **This is a future overlay, not part of any published image.**

Astra initiated this lane; its turn was interrupted by automated content
filtering. Root completed the local C tests, source applicator review and evidence.
No device, binary extraction, network, updater, flash, motor or canonical state
operation was performed. Frozen 3.3 and all earlier images/pins remain unchanged.

## Reproduced production path

The runner verifies every final 3.3 source against its manifest and copies it into
new private scratch. It extracts the entire production `focus_answer_queries`
function; conversion uses the actual focus-map/distance C modules. The real
production dispatcher, ownership, shutdown, frame and packet modules receive
checksum-valid frames through the existing CS callback shim. Two explicit cuts
are after dequeue and before conversion. The IRQ model preserves nested masking
and defers pending callbacks until unlock. Query dequeue/answer counts are
read-only test accessors appended only in scratch.

An ordinary INIT 0x01 at either cut advances the epoch and clears queues, but the
old worker then appends its already-dequeued answer. After completing the new
handshake, its actual 0x06 is 51 bytes and contains that stale query block. Four
additional old-behavior demonstrations execute through the new handshake and
record the wire bytes, independently of the failing assertions. With the
proposal, the next status is 48 bytes and contains no stale answer. Both position
→distance and distance→position queries are exercised with real conversions.

Shutdown and synthetic inhibit/abort policy cuts also demonstrate stale queue
publication. Shutdown prevents any later status emission, so these are queue
state violations rather than demonstrated shutdown-wire faults. A synthetic
`g_aborted` toggle checks policy; it is not claimed to be a real ISR writer.
Replenishing the query queue at each conversion65 times demonstrates an
unbudgeted worker, not proof of a physically attainable camera arrival rate.
The fixed worker leaves unprocessed work queued for later foreground passes.

## Minimal staged fix and controls

The applicator changes only the worker in private `main.c`. Under an outer
saved-mask lock, it captures the session and dequeues. Conversion runs unmasked.
A second short lock checks epoch, handshake, shutdown, motor inhibit and abort
before posting. Every pass is bounded to four iterations. No protocol grammar,
optical table, gain, origin, mailbox layout or public API is changed.

All 22 proposed cases pass under ASan/UBSan; frozen 3.3 fails 18 intended controls
and passes four ordinary/capture controls. Those are scenario invocations, not 18
independent defects. Normal query and raw capture 0x01 status outputs are byte
identical before/after. Capture0x01 does not advance the session. Root's tentative
status-tail queue-underflow hypothesis was rejected: while status ownership is
active, the tested incoming 0x01 is classified as raw capture, not an ordinary
session reset. No such underflow is claimed.
