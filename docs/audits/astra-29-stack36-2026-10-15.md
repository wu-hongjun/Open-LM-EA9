# Follow-up 29 — exact 3.6 stack and compiled EIC handoff

The exact private 3.6 image in `artifacts/private/handoff36a`, SHA-256
`d8a60e48484d1b48e3aff0da18e6d89453d1284a8b23dca01393b320fdc6651f`,
retains a **1,560-byte conservative conditional software stack envelope** against
**8,192 reserved bytes**. All 133 existing static compiler frame sizes are
unchanged from frozen 3.5; the added `em_eic_start` is a zero-frame leaf. There
are no unresolved compiled call edges, dynamic compiler frames or recursive
components in the reviewed image.

The emitted EIC sequence disables IRQ4 before callback publication, preserves
the foreground first-window rescue/reset decision, and enables IRQ4 after
that decision. No new global-mask instruction or enclosing `st_lock` call is
introduced. This is an exact-image static review, not physical IRQ execution,
measured high-water, startup latency or camera qualification. Root owns
integration, build, publication and commits; this lane changes only its own
review files and private scratch. Published lane 22 evidence remains unchanged.

## Emitted EIC ownership order

| Site | Exact compiled behavior |
| --- | --- |
| `em_init:0x5ea0` | Calls `em_eic_init` with linked Thumb `on_cs_edge` and `on_vd_edge` literals |
| `em_eic_init:0x66e4` | Stores `0x10` to NVIC ICER `0xe000e180`: disables IRQ4 only |
| `0x66e6`, `0x66ea` | DSB and ISB before callback publication |
| `0x66f2`, `0x66f6` | Stores CS/VD callbacks to the corresponding symbol-bound globals |
| `0x6754`, `0x6756`, `0x675a` | Initializes EIC flags/enables and peripheral control in setup |
| `0x677e` | Updates EIC priority byte to `0x40`, logical priority 1 |
| `em_init:0x5ec0`, `0x5eca` | Length/header decisions select reset or rescue |
| `0x5ed4` | Calls foreground `on_cs_edge(0)` on the rescue path |
| `0x5f5c`, `0x5f60` | Alternative calls `em_uart_rx_reset`, then branches to common start |
| `0x5ed8` | Both alternatives join the single call to `em_eic_start` |
| `em_eic_start:0x67ac` | Stores `0x10` to NVIC ISER `0xe000e100`: enables IRQ4 only |

The verifier walks every branch in the acyclic compiled suffix beginning with
setup and ending just after start. It finds three structural paths: short
window → reset → start, wrong marker → reset → start, and rescue → start.
Calls are assumed to return for this structural enumeration; it is not a
peripheral execution model. The whole function body digests additionally bind
all instructions and literals, while explicit instruction/word checks establish
the reviewed ICER/ISER addresses, mask, barriers and callback destinations.

`em_eic_start` does not clear NVIC pending or EIC flags. Setup's earlier EIC
flag initialization remains; no claim is made that every edge during peripheral
reset is retained. Deferred enable preserves pending delivery after setup rather
than simulating delivery. UART/SysTick/PRIMASK are not globally masked by this
new handoff. The existing short `st_lock`/`st_unlock` around first-window RX
preservation remains earlier in `em_init`; failure handling can still mask
interrupts. The full mask-operation inventory matches frozen 3.5: `st_lock`
reads PRIMASK and executes `cpsid i`, `st_unlock` restores PRIMASK, and `st_fail`
executes `cpsid i`. The reviewed source and compiled suffix add no call that
wraps rescue in a global critical section. The rejected full-PRIMASK proposal
is not the source or binary reviewed here.

`em_init` retains a 48-byte local frame; `em_eic_init` retains eight bytes;
`em_eic_start` adds zero. Setup and start execute sequentially, so their frames
are not summed as simultaneous allocations. `on_cs_edge` has an 88-byte local
frame and a 140-byte software chain; `on_vd_edge` has eight bytes. EIC invokes
these callbacks sequentially, with a 16-byte handler frame, producing a
156-byte EIC chain. Neither callback reenters servo/pump.

STOCK at `0x957c` contains Thumb pointers `0x7d71`, `0x7e11`, `0x7c65` at
offsets 48, 52, 56. They resolve to pump, retarget and abort. Main's local
`sweep` and `drv` copy STOCK and alter only scalar `v_cruise`/`stop_ms` fields.
Main remains the sole nonzero shutdown/inhibit registrar; `em_init` remains
the EIC callback registrar. Preinit endpoints both equal `0x95e0`; init
`[0x95e0,0x95e4)` contains `0x5129`, Thumb `frame_dummy`.

All 17 runtime bodies without `.su` records were inspected in their exact linked
disassembly. Clone/global-destructor/frame-dummy bodies charge eight local bytes
each. Signed/unsigned switch helpers at `0x90dc`/`0x90f0` each push one word,
restore it and return via adjusted LR: four bytes each. Signed/unsigned division
charge eight bytes for their divide-zero push/call/return path even where valid
operands exclude it. Their modulus wrappers and `__aeabi_idiv0` charge zero
locally while retaining branch target charges. `memmove` at `0x93f0` and
`memcpy` at `0x946c` each push/restore two words; `memset` is a zero-frame leaf.
`__libc_init_array` at `0x9424` pushes four words; `_init`/`_fini` at
`0x95d4`/`0x95e4` push six words, restore all six and return. The policy records
every full-body digest and stack instruction. No missing library frame silently
defaults to zero, and no unaccounted runtime SP write was found.

## Whole-chain envelope and precise entry conditions

The deepest software chain remains:

```text
Reset_Handler 16 → main 104 → focus_exec 96 → focus_run.isra.0 112
→ servo_move_from 136 → pump 8 → em_poll 56 → em_pump_status 40
→ em_transmit 304 → delay_us 16 → st_fail 24 → st_flush 112
→ append 104 → st_write_page 28 = 1,156 bytes
```

| Conditional envelope | Bytes |
| --- | ---: |
| Main and descendants | 1,140 |
| Reset and deepest foreground chain | 1,156 |
| EIC software chain | 156 |
| SERCOM1 software chain | 32 |
| SysTick/default software frame | 0 |
| Foreground plus ordinary default-priority IRQ envelope | 1,416 |
| Foreground plus three active application IRQ chains | 1,452 |
| Foreground plus all configurable levels, HardFault and NMI | **1,560** |

The all-vector result is `1156 + 156 + 32 + 6 × 36`. Each exception conservatively
charges eight core words plus an alignment word. ARMv6-M supplies four
configurable preemption levels plus HardFault/NMI and no floating-point frame.
Unused implemented vectors resolve to the zero-frame default handler; reserved
slots are checked as zero. Same/lower-priority pending exceptions and tail
chaining do not create unbounded stack recursion. The graph charges tail calls
as additional full frames, overestimating. The deepest path includes `st_fail`;
this review conservatively does not subtract configurable IRQ overlap suppressed
by its global mask. The 6,632-byte difference from the reservation is conditional
arithmetic headroom, not a runtime guard or high-water observation.

The checked servo/homing query-conversion paths remain 552/208 bytes; their
predictor/division counterparts remain 504/160 bytes. Calls within a pump are
sequential and use their maximum descendant, not their sum. The unused relative
servo wrapper is absent from the final ELF (its source `.su` remains 16 bytes).
Diagnostic PARK and diagnostic-build stack behavior are outside this release.

[Audit 24](astra-24-boot-entry-2026-10-15.md) supplies the more precise original
boot contract. Its finite composed trace concerns frozen **3.5** and has no
interrupt scheduler; it must not be presented as execution of 3.6 or physical
IRQ delivery. The 3.6 startup source is byte-identical by manifest, its reset
handler remains at `0x5150` with a 16-byte frame and the same MSP/VTOR semantics,
and its actual vector/layout are rechecked here. Under privileged thread mode,
`CONTROL=0`, `PRIMASK=0`, no active exception, reset peripheral defaults and no
outside interference, the original PA23-low path loads the new application MSP
and selects VTOR. Main entry therefore retains the 16-byte reset frame at
`0x20002be8`; boot frames cease being live on the selected application stack.

The original path **preserves** CONTROL, PRIMASK, priorities and unrelated
interrupt state. It enables NVMCTRL IRQ5 after clearing its pending bit while
its peripheral INTEN stays reset-zero. Boot SysTick runs with TICKINT clear;
the app later enables SysTick and SERCOM1 without setting their priorities.
Only EIC priority 1 is explicitly programmed. The NVMCTRL vector still resolves
to `Dummy_Handler`: an unexpected delivered IRQ5 would loop, but this review
supplies no ordinary-reset cause for such delivery. Non-reset state must not be
misrepresented as a demonstrated cold-start defect.

The original MSP/VTOR transition is unmasked and has no handoff DSB/ISB; the new
EIC-disable barriers do not retroactively establish atomic boot handoff.
Physical core/stack selection, asynchronous arrivals/active exceptions,
NMI/HardFault transition behavior, memory corruption and failed stacking remain
outside this proof. The model requires valid control flow and intact callback
configuration. No stack watermark, guard/canary, physical IRQ duration, NVM
latency, camera, optical or motor measurement was made. Stack capacity implies
no elapsed-time or interrupt-latency guarantee.

## Guards, reproduction and limits

The [guard output](../../firmware/upstream-hardening/followup/29-stack36/guards.json)
contains **29 rejected negative controls and one accepted exact-bound control**.
The inherited 20 negatives cover input/source/compiler integrity, unknown or
recursive callbacks, library evidence/charges, layout, inventory, physical
caveats, raw/ELF/image correspondence and unsupported unconditional safety.
The nine additional controls reject a branch bypassing rescue/reset, a missing
deferred start, missing IRQ4 disable/enable, missing DSB/ISB, an NVM vector
rebound to EIC, a STOCK pointer rebound to abort, and a new global mask.

Instruction/word mutations for the additional guards occur only in Python
copies; they directly test the semantic subchecks without being stopped by an
outer digest. File-mutation controls use disposable private build copies. Only
the two inner byte-comparison controls refresh their copied outer raw/image pin
to reach the intended independent check. This is evidence fault injection,
not executable firmware fault injection or a physical interrupt experiment.
Original candidate inputs are rechecked after controls. Policy pins are never
refreshed by the runner.

```sh
python3 firmware/upstream-hardening/followup/29-stack36/run.py \
  --build artifacts/private/handoff36a \
  --output artifacts/private/astra-29-stack36-recheck.json \
  --guards-output artifacts/private/astra-29-stack36-recheck-guards.json
```

A copied build must match the original pins. A root-owned path-container-only
ELF/map reproduction needs explicit normalized disassembly/symbol/program-header
equality and separately derived pins, preserving this audit's original policy
and semantic checks. No network, device enumeration/open, reports, flash,
updater, app launch, motor operation, canonical state write or commit occurred.
