# Follow-up 18 — exact 3.4 compiled stack review

The proposed 3.4 build in `artifacts/private/bounded34b`, including follow-up 17's
homing inhibit guard, has a **1,560-byte conservative conditional software stack
bound** against an **8,192-byte linker reservation**. The new nested
servo → pump → query conversion path totals 552 bytes including the live reset
frame; the inlined homing → pump → query path totals 208 bytes. Neither exceeds
the existing transmit/fail-stop path. No recursive component, unresolved compiled
call edge or dynamic compiler frame was found.

This is an exact-image static review, not measured high-water, a camera test or
an unconditional physical stack-safety claim. All entry/IRQ caveats from the
[frozen 3.3 review](astra-14-stack-2026-10-15.md) remain. The final 3.4 ELF was read
without rebuilding, extracting a new binary, modifying firmware, accessing a
device or touching canonical application state. The earlier `bounded34a` review
was preliminary and is not the pinned result below.

The deepest foreground chain is unchanged:

```text
Reset_Handler 16 → main 104 → focus_exec 96 → focus_run.isra.0 112
→ servo_move_rel 136 → pump 8 → em_poll 56 → em_pump_status 40
→ em_transmit 304 → delay_us 16 → st_fail 24 → st_flush 112
→ append 104 → st_write_page 28 = 1,156 bytes
```

The compiled query worker has a 48-byte local frame: five pushed registers plus
28 bytes of local storage. Its largest child chain is 32 bytes for either
conversion. Position-to-distance reaches `focus_distance_code 8 → distance_mm 16
→ __udivsi3 8 → __aeabi_idiv0 0`; distance-to-position reaches
`focus_counts_for_code 16 → focus_exp2_q6 16`. The runner explicitly verifies
every compiled edge in these paths rather than appending source-level names to
the result. The servo prefix before the worker is 472 bytes, yielding 552.
Homing is inlined into main in this build, so its prefix is `Reset 16 + main 104
+ pump 8`, yielding 208 with the worker/conversion chain.

Query service returns before `em_poll()` starts. Their child frames therefore
use a maximum, not a sum. No poll, shutdown, query or conversion callback returns
to servo/pump. Foreground repeated service passes do not accumulate stack depth.
The new homing inhibit guard adds a compiled call but no new maximum frame or
recursive path. The all-vector total is the 1,156-byte foreground bound plus
156-byte EIC and 32-byte SERCOM1 chains and six 36-byte exception allowances.

## Entry, IRQ and physical limitations retained

The linked reservation remains `[0x20000c08,0x20002c08)`, with 3,076 bytes of
static RAM plus four alignment bytes below it. The arithmetic difference between
the 1,560-byte bound and the reservation is 6,632 bytes. A linker reservation is
not a runtime stack guard or a high-water measurement.

Existing stock boot evidence at `0x2510` establishes the intended load of MSP
from the application vector at `0x5000`, VTOR assignment to `0x5000`, and call to
the application reset vector. This is the same high-confidence static
reconstruction as lane 14, evidence
`ev_af84eb17e704f414c6a70060f43666c376cc40e1828175a44552db137154b0c6`.
Physical execution of that path, CONTROL/PSP selection, PRIMASK and inherited
vector-transition state remain unverified. The conditional model requires that
thread-mode frames actually use the intended application stack.

The application explicitly programs only EIC's priority. SERCOM1/SysTick
priorities, other inherited enabled/pending IRQs and transition interrupt state
remain open. Two implemented priority bits allow at most four configurable
preemption levels; HardFault and NMI contribute two more. Each exception is
charged eight core words plus one possible alignment word, 36 bytes. There is no
floating-point context. Same/lower-priority pending interrupts and tail-chaining
do not create an unbounded recursive exception stack. The six-frame envelope
conservatively overcounts combinations that EIC's fixed priority can exclude.

`st_lock` saves PRIMASK and disables maskable interrupts; `st_unlock` restores
that saved key; `st_fail` disables them permanently. The bound does not subtract
maskable-IRQ overlap from the deepest failure tail, so it is conservative there.
NMI and HardFault remain possible. The model assumes valid control flow, intact
callback/configuration memory and ARMv6-M execution. It excludes memory
corruption, bootloader stack execution and failure of exception stacking itself.
There are no new physical stack-watermark, guard/canary, ISR-duration, NVM timing,
motor-rest or camera-behavior measurements. These remain separate acceptance
gates; neither stack headroom nor this audit closes them.
